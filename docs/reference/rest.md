# REST API

Повний перелік HTTP-ендпоінтів. Таблиці нижче згенеровані з коду сервера, тож
відповідають поточному стану гілки.

## Як читати колонку «Доступ»

| Значення | Що потрібно надіслати |
|---|---|
| `публічний` | нічого |
| `art-токен` | `X-Art-Token` або `?token=` |
| `art + audio токен` | `X-Art-Token` + `X-Audio-Token`, або `?artToken=&audioToken=` |
| `адмін (JWT)` | `Authorization: Bearer <token>` з `/api/admin/login` |
| `адмін (bearer або query)` | те саме, але токен приймається і в query — для `<audio src>` |

Колонка «Привілей» стосується лише адмінських ендпоінтів і працює **додатково**
до JWT: обліковий запис має бути або супер-адміном, або мати цей привілей.
Детальніше — [Привілеї](/reference/privileges).

## Формат помилок

Помилки повертаються з полем `error`, і його значення **не завжди рядок** —
частина ендпоінтів віддає об'єкт з усіма локалями. Обов'язково прочитайте
[Формат повідомлень та i18n](/protocol/messages), перш ніж писати обробку.

## Про колонку «Привілей»

Два записи означають різне, і плутати їх не можна:

| Запис | Зміст |
|---|---|
| `A + B` | потрібні **обидва** привілеї |
| `A або B` | достатньо **будь-якого** |
| `…` *(посекційно)* | потрібний привілей залежить від того, що саме змінює запит |

## Стан опису

Таблиці генеруються з коду, тож перелік завжди повний. Детальні описи —
параметри, тіла запитів і відповідей — пишуться вручну, і **зараз описано всі
ендпоінти**.

Щоб змінити опис, відредагуйте `reference/annotations/endpoints.mjs` і
перезапустіть `npm run extract`. Ключ — рівно `МЕТОД /шлях` з таблиці; якщо
описати ендпоінт, якого в коді немає, перевірка впаде.
